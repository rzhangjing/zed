## settings 家族与 project/worktree/git 关系小结

1. settings 家族自下而上四层：`settings_json`（纯 JSON 文本工具，只依赖 util）→ `settings_content`（纯数据：`SettingsContent` + 各域结构，依赖 settings_json + settings_macros，**不依赖 settings/fs**）。
2. `settings_macros` 是 `proc-macro = true` 的代码生成 crate，只依赖 quote/syn；对 settings 的引用是 dev-dependencies（settings_macros/Cargo.toml:22-23），只构成 dev-only 环。
3. `settings` 是唯一运行时层：SettingsStore/settings_file/keymap_file/editorconfig_store/vscode_import，`settings_store.rs:795` 调 `migrator::migrate_settings`，并在 settings.rs:33 `pub use ::settings_content::*` 把数据层重新导出给全仓使用。
4. 流向单向：settings_json → settings_content → settings → {settings_ui, settings_profile_selector}；`migrator` 横切消费 settings_content+settings_json，只被 settings（:795）与 zed 调用。
5. `settings_ui` 是 UI（设置窗口 + pages/components），`settings_profile_selector` 只是 profile 模态选择器，动作本身定义在 zed_actions:539，二者都不参与设置解析。
6. project 是中心聚合器（RevN=60）：`project.rs:1-25` 列出 worktree_store/buffer_store/git_store/lsp_store/task_store/terminals/prettier_store/toolchain_store/context_server_store 等 store。
7. worktree 是「单棵树」模型（依赖 fs::Watcher/PathEvent、gitignore 栈、language 编解码、git 常量），被 project 聚合成 worktree_store；client 直接依赖 worktree 做远端同步。
8. fs 是底层文件系统门面（RealFs/FakeFs + fs_watcher + git_clone_progress），git 是纯 Git 封装（repository/status/blame/commit/stash + 托管提供者注册表），两者互不依赖（fs 仅 dev-dep 引 git）。
9. `db` 与 project/worktree **不在同一条依赖链上**：project 的 In、db 的 Rev 互相都不含对方；db 是被 workspace/editor/session/git_ui/git_ui_core 等 29 个 crate 使用的本地持久化层，project 的持久化走 client/rpc。
10. git_ui_core 是可复用底座（worktree 选择/文件 diff/askpass，RevN=6），其 `AnyView`+builder 设计明确为避免反向依赖上层 crate（git_ui_core.rs:18-22）；git_ui 依赖它提供完整 Git 面板（RevN=3，其中 vim/project_panel 为 dev-dependency）。
11. 语言四件套职责不重叠：`languages`=各语言语法/LSP 适配器实现（再导出 language 核心），`language_selector`=切当前 buffer 语言，`language_tools`=语法树/LSP 日志等开发者视图，`language_onboarding`=Python 引导横幅。
12. 活跃度：journal/system_specs/migrator/node_runtime/toolchain_selector/git_hosting_providers 在 crates/zed/Cargo.toml 均为非 optional 依赖且在 main.rs/zed.rs 初始化；prettier 未被 zed 直接依赖，仅经 project::prettier_store（project/Cargo.toml:74，非 optional）传递生效。
