## 编辑器数据层与 LSP/DAP 链路小结

1. 自下而上单向分层：`rope`（纯 rope/Point/OffsetUtf16 结构，无业务依赖）→ `text`（在 Rope 上做 CRDT 操作/History/undo/Patch：`Buffer` text.rs:59-66、`BufferSnapshot{visible_text,deleted_text,base_text: Rope}` text.rs:113-115、`pub use rope::*` text.rs:24）→ `multi_buffer`（把多个 `text::Buffer` 的 excerpt 拼成一个可编辑视图：multi_buffer.rs:74-81）。
2. `buffer_diff` 不存文本，只维护"base ↔ 当前 buffer"的 diff 快照与 hunk 状态（buffer_diff.rs:22-28），git 暂存/还原经 `DiffOperations` trait，实现于 project/src/git_store.rs:321；`multi_buffer` 为每个 buffer 持有 `DiffState` 并用 `DiffTransforms`(multi_buffer.rs:1131) 映射 hunk 行。
3. `streaming_diff` 是独立于 editor 的线性 diff 引擎（streaming_diff.rs:130/149/315），面向 AI 逐块输出，唯一生产消费者是 `agent/src/edit_session.rs:25,392,613`。
4. `editor` 是 UI+编排层，自身不存文本：`Editor { buffer: Entity<MultiBuffer> }`(editor.rs:951/955)，子模块 `display_map`（坐标/折行/fold/inlay 映射）与 `element`（渲染）；`breadcrumbs` 与其构成反向依赖（editor.rs:361 注入 `breadcrumbs::RenderBreadcrumbText`）。
5. 语言栈三层：`language_core`（无 gpui 的类型/接口层：Grammar/LanguageConfig/LanguageQueries/Toolchain/适配器状态枚举）→ `grammars`（20 个内建 tree-sitter grammar + fs_embed 内嵌 config.toml/queries，grammars.rs:8-46）→ `language`（运行时 Language/LanguageRegistry/SyntaxMap，language.rs:941、syntax_map.rs:131）。
6. `LspAdapter` trait 住在 `language`(language.rs:511) 而不是 `lsp`：`lsp` 只做 JSON-RPC 收发与 server 二进制描述（lsp.rs:115/95、input_handler.rs:30）。
7. `syntax_theme` 是纯数据（capture→HighlightStyle，syntax_theme.rs:14-17），唯一消费者 theme；`language_detection` 是内容采样 + `betlang` 模型检测（language_detection.rs:62-80），唯一消费者 editor。
8. LSP 功能的统一模式：**协议在 lsp、编排在 project、各自的 UI 在自己的 crate**——`lsp_locations`（picker UI，:249/586）、`project_symbols`（project.symbols，:222）、`call_hierarchy`（project.prepare/incoming/outgoing_calls，:408/90/100）都只调 project/lsp API。
9. `diagnostics` 是项目诊断的**UI**（ProjectDiagnosticsEditor 实现 Render/Item，diagnostics.rs:96/732），诊断数据实体在 `language::DiagnosticSet`；`debugger_tools` 也纯 UI（DAP 日志工具栏，dap_log.rs:73/494/504）。
10. DAP 链路：`dap` = 协议客户端 + 传输 + 注册（client.rs:32、transport.rs:649/472/739、registry.rs:41/16、adapters.rs:194/108）→ `dap_adapters` = 具体适配器（codelldb/gdb/go/javascript/python，dap_adapters.rs:29）→ `debugger_ui`（非本组，面板）与 `debugger_tools`（日志工具栏）；`editor` 也直接观察调试会话（editor.rs:2653 observe `project::debugger::session::Session`）。
11. 进程层归属明确：`terminal` 管 PTY/alacritty（terminal.rs:4-5、HeadlessTerminal:86）→ `terminal_view` 管 GPUI 视图/面板（terminal_view.rs:130/1328）→ `repl` 自建 Jupyter 内核进程（kernels/native_kernel.rs:151 `util::process::Child::spawn`）并复用 terminal_view 的元素渲染输出。
12. 使用状态与残留：30 个 crate 全部仍在 cargo metadata 依赖图内且都被 `zed` 间接依赖；`zed/src/main.rs` 显式 init 的有 debugger_tools:562、dap_adapters:609、snippet_provider:621、repl:639/648、diagnostics:649、go_to_line:655、outline:658、call_hierarchy:659、project_symbols:660、search:665、lsp_locations:666、terminal_view:677、encoding_selector:679、line_ending_selector:681，状态栏/工具栏项见 zed/src/zed.rs:592/596/616/618/1366/1379/1385。残留项：search/src/buffer_search.rs 的 mac 剪贴板取词分支在 Windows 恒不编译；text/src/network.rs 仅测试使用；diagnostics/Cargo.toml:16 的 `agent_settings` 依赖无任何代码引用；editor 仍带 collaborator 类型（editor.rs:141/994）。
