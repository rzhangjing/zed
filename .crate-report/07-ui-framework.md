## 主题/组件基础设施小结

1. **两层主题栈**：`theme` 是"数据与渲染层"（ThemeColors/ThemeStyles/IconTheme/ThemeRegistry/schema，49 个消费者，零 settings 依赖）；`theme_settings` 是"设置桥接层"（ThemeSettings + schema，46 个消费者，持有 settings 依赖）。二者用 `theme::ThemeSettingsProvider` trait 反转耦合（`crates/theme/src/theme_settings_provider.rs:9-24`），避免 theme → settings 的硬依赖。
2. **UI 交互入口**：`theme_selector`（RevN=1，仅 zed 装配）负责主题/图标主题的模态选择与 `update_settings_file` 持久化；`theme_importer`（RevN=0）是纯 CLI 工具，只被 `script/import-themes` 调用，不参与运行时链路——可视为可选开发工具。
3. **组件基础设施三件套**：`component`（trait + inventory 注册表 + 预览布局）、`ui_macros`（`RegisterComponent` 派生，仅 ui 使用）、`component_preview`（预览宿主）。`ui` 借 `component_prelude` 转发三者，因此 `ui`(RevN=63) 是所有 UI crate 的唯一通用入口。
4. **ui / ui_input 的边界**：`ui` 只放不依赖 `editor` 的原语；`ui_input` 需要编辑器能力，故用 `ERASED_EDITOR_FACTORY` 工厂反转依赖，实际注册点在 editor，取用点在 picker——这是本组里唯一一处刻意的依赖反转设计。
5. **picker 家族分工**：`picker`(RevN=29) 提供 Picker/PickerDelegate + `Preview`/`PreviewBackend` 抽象；`picker_preview`(RevN=5) 只提供"编辑器实现"这一具体后端，是真实运行时依赖（file_finder/search/outline/lsp_locations/project_symbols），**不是开发预览工具**。`component_preview` 才是开发/预览工具（虽已编入 zed 主程序）。
6. **command_palette 与 picker**：命令面板复用 picker 作为渲染底座，`command_palette_hooks` 则是解耦出来的"谁能出现在面板里"的全局过滤器（RevN=10），由各功能面板自行登记隐藏规则，避免面板反向依赖 command_palette。
7. **文件/通知类小件**：`file_icons`(RevN=17) 从 IconTheme 解析图标，是编辑区/面板的公共依赖；`notifications` 目前只剩 `status_toast` 一个模块；`icons` 是零依赖的图标名枚举；`menu` 是零渲染的动作命名空间（RevN=35）。
8. **mac 残留现状**：`platform_title_bar` 的 mac 分支已彻底清除（`platforms.rs` 只剩 linux/windows）；`title_bar` 仍有 8 处 `#[cfg(not(target_os = "macos"))]` 反向守卫，`ui` 仍保留 traffic-light 常量——均为只读备注，未做改动。
