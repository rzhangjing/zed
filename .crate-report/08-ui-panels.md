## 面板挂载关系小结

1. 组内只有两个真 `Panel`：`outline_panel::OutlinePanel`（`outline_panel.rs:5131`）与 `debugger_ui::DebugPanel`（`debugger_panel.rs:1513`）；两者都在 `zed.rs:767-771` 构造、`:789-793` 经 `add_panel_when_ready` → `workspace.add_panel` 挂载，菜单入口 `app_menus.rs:43`（Outline Panel）与 `:45`（Debugger Panel）。
2. 其余"预览/编辑类"都是编辑器 **Item**（进入 pane 而非 dock）：`ImageView`、`SvgPreviewView`、`TabularDataPreviewPane`、`KeymapEditor`、`Onboarding`、`DebugSession`/`SubView`；由各文件动作（`svg::OpenPreview`、`tabular_data::OpenPreview`、`zed::OpenKeymap`、`OpenOnboarding`）打开。
3. 弹出类都是 **ModalView**：`TabSwitcher`、`RecentProjects`、`WhichKeyModal`、`ScopeSelector`、`TasksModal`、`BaseKeymapSelector`、`AttachModal`/`NewProcessModal`、`KeybindingEditorModal`、`ThreadSwitcher`。
4. `sidebar::Sidebar` 既不是 Panel 也不是 Item：它实现 `workspace::multi_workspace::Sidebar` trait（`multi_workspace.rs:119`），经 `register_sidebar`(:385) 注册，`zed.rs:526-536` 挂到 MultiWorkspace；能否打开取决于 `!disable_ai && agent_settings.enabled`。
5. 状态栏挂载：`ActivityIndicator` 左端（`zed.rs:594/629`）、`image_viewer::ImageInfo` 右端（`:604/636`）、`vim::ModeIndicator` 与 `which_key::PendingKeystrokesIndicator` 右端末位（`:601-603/638-639`）。
6. 无 UI 挂载点：`input_latency_ui`（无 `init`，仅遥测 + 一个 dev 动作）、`vim_mode_setting`（纯设置）、`miniprofiler_ui`（按设置开关命令面板项）、`inspector_ui`（debug/Nightly 才启用）。
7. 依赖侧证据：这 20 个 crate 在 `zed/Cargo.toml` 全部是无条件 `X.workspace = true`；唯二开关是 `inspector_ui` 的 `feature = "inspector"` 与 `tabular_data_preview` 的 `dev-tools`（后者无人启用）。
8. `open_path_prompt` 是"被复用"而非被淘汰：`file_finder::init` 主动注册它，`recent_projects` 对它的 Cargo 依赖是死依赖。
9. CSV 的 `In` 列混入 dev-dependencies（`vim` 最明显），判断真实运行时耦合时需回看 `Cargo.toml` 的 `[dev-dependencies]`。
10. 预置键位入口（`assets/keymaps/default-windows.json`）：`tab_switcher` 680-681、`outline_panel` 687/942-947、`tabular_data` 612-613、`recent_projects` 1199-1203、`keymap_editor` 1356-1363、`onboarding` 1400、`image_viewer` 1499-1505。
